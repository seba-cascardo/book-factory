## 1. Principles for every doc change

1. **Rules in agent files, history elsewhere.** Measurements and war stories ("221 of
   454", "30 of 474", "6 of 6 vs 0 of 2", "three months", "seventeen days", Qlik
   anecdotes) move to `docs/rationale/<area>.md`. The agent file keeps the rule plus,
   at most, one line: `Why: docs/rationale/<area>.md#<anchor>`.
2. **Size budget.** Every doc owner reports before/after character counts of the files
   it owns. Target: **−25% net** across your files while adding the new content.
3. **One home per rule.** Never restate a rule owned by another file; point to it. The
   verdict computation lives only in `references/rubric.md`.
4. **Language-aware.** No English-only word lists in prose. Lists live in
   `scripts/lexicons/<lang>.yaml`; docs point there. Spanish dialogue uses the raya (—):
   no rule may count dialogue rayas as em-dashes.
5. **Counted means counted by a script.** Anything the rubric calls a count comes from
   `drafts/unit-NN/checks.json` (§3). Agents copy numbers; they never recount.

## 2. Execution model (D2 writes it in `pipeline.md` and SKILL.md)

- The **orchestrator** is the session running the skill. It dispatches every agent as a
  **subagent** (Agent/Task tool) with: the agent file, the profile file, and the exact
  input list from the contract tables; plus output paths. The orchestrator never
  drafts unit prose itself. Tier → `models.tiers.<tier>`; `inherit` = no override.
- **Must** be isolated subagents with a closed input list: Critic, Reader-POV (every
  mode), adversarial skeptics and refuters, concept/rule auditors, Continuity Guardian
  Mode A. **Should** be subagents: Writer, Technical Reviewer, Editor, Humanizer,
  Proofreader, CG Mode B.
- **Cold readers** (Reader-POV, Skeptic C) read `drafts/unit-NN/humanized.clean.md`
  (HTML comments stripped by `pipeline_step.py clean`), never `humanized.md`.
- **Dispatch brackets.** Before each agent: `python scripts/pipeline_step.py check
  unit-NN <agent>` (non-zero → do not dispatch; fix the input). After:
  `python scripts/pipeline_step.py done unit-NN <agent> --tier <t> --cycle <n>`
  (verifies the output exists and is non-empty, appends the runs log, records role
  diffs). An empty/`null` output → re-dispatch once; a second failure → stop and tell
  the human. Never gate on a missing artifact.
- Before the Critic: `python scripts/pipeline_step.py checks unit-NN` →
  `drafts/unit-NN/checks.json` + `checks.md`.
- **Runs log** moves out of `project-status.yaml` into `runs.tsv` at the project root
  (written only by `pipeline_step.py done`).
- **Cross-model option.** `pipeline.adversarial_verify.cross_model: true` dispatches the
  refutation pass (and, at the manuscript gate, one lens) to a second model when a tool
  is available (e.g. a Codex MCP tool or the user's `debate` skill); otherwise the packet
  says "cross-model unavailable".

Agent names used by `pipeline_step.py`: `writer`, `technical_reviewer`, `editor`,
`humanizer`, `reader_pov`, `continuity_a`, `critic`, `adversarial`, `proofreader`,
`continuity_b`, `digest`.

## 2.1 Pipeline order (v3.4)

**Nonfiction (fast):** Writer → Technical Reviewer → Editor → Humanizer → CG Mode A →
checks → Critic → [Adversarial] → **Proofreader** → Human review → (approve) copy to
`final/` → CG Mode B → digest → archive.
**Nonfiction (full):** as fast, plus Reader-POV after the Humanizer.
**Literary:** Writer (scene by scene) → Editor (assembly/structure) → Humanizer →
Reader-POV → CG Mode A (literary) → checks → Critic → [Adversarial] → **Proofreader** →
Human review → (approve) copy to `final/` → CG Mode B → digest (literary template) →
reader-journal update → archive.

The Proofreader moves **before** human review, so the human approves exactly the text
that ships; its diff (`role-diff-proofreader-*.json`) is in the human packet.

## 2.2 Loop semantics (D2 in `pipeline.md`; D1 applies to literary agents)

- Loopback targets are exactly: `Writer | Editor | Humanizer | escalate`.
  `Reader_POV_plus_Humanizer` is **removed**.
- Before any loopback: `pipeline_step.py snapshot unit-NN` copies `humanized.md` to
  `humanized.cN.md`.
- Every target reads its **worklist**: `critique.md` § Specific loopback instructions +
  the failing items; plus the triggering report (`tech-review.md` for a Reviewer REVISE,
  `adversarial-report.md` for an adversarial REVISE, `human-notes.md` for a human
  rejection — the orchestrator appends dated human notes there).
- **Writer, REVISE:** input = the latest `humanized.md`; output = a new `draft.md` that
  is that text with targeted fixes only. The whole chain downstream re-runs.
- **Writer, REWORK:** fresh draft from outline + critique. The whole chain re-runs.
- **Editor / Humanizer:** patch `humanized.md` in place (after the snapshot). Then only
  what follows re-runs: Reader-POV (if any `reader_pov` item failed last cycle, or
  literary always) → CG Mode A → checks → Critic. `check_role_diff` enforces that the
  Editor added no prose.
- **Plateau rule:** if a cycle resolves none of the previous cycle's failing items (same
  or larger failing set), stop and produce the escalation packet immediately, whatever
  the retry budget.
- Retry caps unchanged (2 fast, 3 full/literary).

## 2.3 Routing fixes

- Literary `reader_pov-1` (comprehension) → Writer; `reader_pov-2` (would close the
  book) → Writer; `reader_pov-3` (pacing) → Editor; new `reader_pov-4` (predictability,
  from the reader journal) → minor, observation only.
- Nonfiction `reader_pov-1` → Humanizer (clarity rewrite is in its scope);
  `reader_pov-2` → Writer; `reader_pov-3` (outcome) → Writer.
- Humanizer budget exceeded (from `checks.json → role_diff.humanizer.over_budget`) is a
  rubric item routed to the **Writer** (literary `voice-6`; nonfiction `voice-8`).

## 3. Script interfaces (S2 implements; everyone else references exactly these)

Common: all accept `--root <project>` (default: cwd walk-up to `bible/meta.yaml`), read
UTF-8 with BOM tolerance, and resolve the language as `project.language_variant` →
`conventions.language_variant` → `project.language` → `en`. JSON outputs are UTF-8,
`ensure_ascii=False`, sorted keys.

### `count_rhet.py`
`python scripts/count_rhet.py [--root R] --unit unit-NN [--file PATH] [--json OUT]`
Default file `drafts/unit-NN/humanized.md`. Excludes code fences, tables, HTML comments,
headings (except for rhet-7), and — literary — dialogue (raya lines and quoted speech).
Quotas: rubric defaults, overridden by the ```yaml fence containing `rhetoric_budget:`
in `bible/voice-profile.md`. Output:
```json
{"unit":"unit-07","file":"...","language":"es","pack":"es","profile":"book-literary","words":4826,
 "counts":{
  "rhet-1":{"count":1,"quota":2,"lines":[88]},
  "rhet-2":{"count":2,"quota":1,"matches":[{"line":140,"text":"..."}]},
  "rhet-3":{"count":0,"quota":2,"terms":[]},
  "rhet-4":{"hit":false,"closing":"..."},
  "rhet-5":{"bolds":0,"per_1000":0.0,"quota":8},
  "rhet-7":{"headings":[]},
  "ai_vocab":{"count":0,"hits":[]},
  "weasels":{"count":3,"hits":[...]},
  "em_dash_narration":{"count":2,"per_page":0.4},
  "speech_verbs_ornate":{"count":1,"hits":[...]},
  "sentence_length":{"mean":11.2,"sd":6.1,"flat_runs":2}}}
```
Items not applicable to the profile are omitted (literary: only rhet-2 of the rhet family).

### `check_identifiers.py`
`--build-index` writes `bible/identifier-index.txt` from `bible/sources/*.md` (call
patterns `Name(`, backticked identifiers, code in sources); a `# allow` section written
by hand survives rebuilds. Check mode: `--unit unit-NN [--file]` or `--units GLOB`
→ JSON `{"unknown":[{"identifier","locations":["file:line"],"in_code":true}],
"index_size","checked"}`. Known = index ∪ glossary terms ∪
`meta.validation_surface.identifier_allowlist` ∪ built-in keywords of
`conventions.code_language`. Exit 0 unless `--fail-on-unknown`.

### `check_role_diff.py`
`--role editor|humanizer|proofreader --before A --after B [--budget 0.03] [--json OUT]`.
Sentence-level diff (Spanish ¿¡ and raya lines handled; HTML comments ignored). Output:
`{"role","words_before","sentences_added","sentences_removed","sentences_modified",
"added_words_ratio","touched_ratio","over_budget","violations":[...],"changes":[...]}`.
Editor violation: added prose beyond transitions (`added_words_ratio > 0.02`).
Humanizer: `over_budget` when `touched_ratio > budget` (literary default 0.03; nonfiction
reports only). Proofreader: `changes` lists every changed sentence for the human.

### `pipeline_step.py`
- `check unit-NN <agent>` — preconditions per profile (inputs exist and are non-empty).
  Literary `writer`: also `check_story.py --unit unit-NN`. Exit 0/1 with the list.
- `done unit-NN <agent> --tier T --cycle N` — output exists, non-empty, not `null`;
  appends `runs.tsv` (`unit agent tier cycle timestamp_utc output_bytes`); for
  editor/humanizer/proofreader writes `drafts/unit-NN/role-diff-<agent>-c<N>.json`.
- `clean unit-NN` — writes `humanized.clean.md`.
- `snapshot unit-NN` — copies `humanized.md` to the next `humanized.c<N>.md`.
- `checks unit-NN` — runs count_rhet, check_identifiers (nonfiction), lint_fiction
  `--unit` + check_story `--unit` (literary), and collects the latest role diffs into
  `drafts/unit-NN/checks.json` + `checks.md`.
- `ready` — literary: `check_story.py --ready-to-draft`; nonfiction: outline exists and
  is approved, KG constraint met where the profile requires a KG. Exit 0/1 + blockers.
- `apply-edits EDITS.yaml [--dry-run]` — applies anchor edits
  (`[{unit, find, replace, rule}]`) to `final/`; the whole batch fails if any `find` does
  not match exactly once. Replaces LLM-generated unified diffs in the polish pass.

### `lint_fiction.py`
`[--root R] (--unit unit-NN [--file F] | --book [--units GLOB]) [--json OUT]` →
`{"findings":[{"rule","severity":"info|minor|major","unit","line","detail"}],"stats":{...}}`.
Rules: `dialogue_ratio`(info), `sentence_stats`(info), `sentence_run`, `repeated_ngram`
(book: 3–6-grams in ≥3 units), `gesture_tic` (lexicon `gestures`, per 1000 words and
across units), `paragraph_opener`, `cliche`, `speech_verb_ornate`, `unknown_name`
(capitalized non-initial tokens not in sheets/aliases/extras/world → **major**, text
"NEW-CHARACTER?"), `near_duplicate_name`, `attribute_mentions` (eyes/hair/age per
character; conflicting values → minor), `dialogue_format` (raya vs hyphen/en-dash, quote
mixing, dialogue glued to narration → major), `ordered_list_hazard` (prose paragraph
starting `1999.` → major), `scene_break_mix`, `unit_length` (vs `target_words` ±30%),
`opening_repeat` (same opening type 3 units running, or first-line similarity ≥0.5 →
minor).

### `check_story.py`
`[--root R] (--ready-to-draft | --unit unit-NN | --manuscript) [--json OUT]` →
`{"findings":[{"code","severity":"blocking|major|warning","subject","detail","location"}]}`.
Exit 1 if any `blocking` (or `major` in `--manuscript`), else 0. Codes:
`CHAR-INCOMPLETE`, `CHAR-NO-ARC`, `CHAR-ARC-OUT-OF-OUTLINE`, `CHAR-UNKNOWN`,
`EXTRA-PROMOTE`, `NEW-CHARACTER` (unit mode, from the draft's unknown names),
`ENDING-MISSING`, `ARC-AFTER-ENDING`, `ARC-NOT-RESOLVED` (manuscript), `LEDGER-NO-PAYOFF`,
`LEDGER-OPEN` (manuscript), `SEEDS-MISSING`, `CALIBRATION-NO-HUMAN`,
`ENDING-NOT-DELIVERED` (manuscript: `final_unit` not in `final/`).

## 4. Gate changes (S1)

**P0 bugs (from the review, §5.2):** G1 `converged()` must require an acceptable verdict
and zero open critical/major; G2 count distinct rounds, not invocations, and count MG-5,
MG-7 and MG-S blocking findings as new blocking; G3 open findings persist across rounds;
G4 tool failures are loud (verdict `ERROR`, exit 2), stale outputs are cleaned before a
run, missing outputs are never read as `{}`. Plus G5–G16 and the low-severity list.
**Every P0 gets a regression test in selftest.**

**Simplification (P3):**
- `reviews/manuscript-gate-<run>/findings.jsonl` — cumulative store. Every finding,
  every round, with a content key and status `open|fixed|refuted|accepted-risk`. Open
  findings persist until resolved (`manuscript_gate.py --resolve KEY --status S --note
  N`, or a re-audit of the subject that no longer reports the key). The verdict is
  computed over all open findings.
- `subjects.json` — manifest keyed by **content** id, states
  `pending | audited@<hash> | sampled`. An edit changes the hash and returns the subject
  to `pending`.
- **One waiver type**, `manuscript_gate.coverage`, signed over the (pending, sampled)
  id sets. Verdicts: `ERROR | BLOCKED | NEEDS-REVISION | PASS-PARTIAL | PASS`
  (PASS-SAMPLED merges into PASS-PARTIAL; the report still separates never-opened from
  partly-read). `rule-probes-tuned.yaml` stays as an optional narrowing input.
- Converged ⇔ (`PASS`, or `PASS-PARTIAL` with a valid coverage waiver) AND no open
  critical/major AND the last 2 distinct rounds introduced no new blocking findings.
- `state.json` is the gate's source of truth; `project-status.yaml` keeps only a pointer
  (fix the doc, do not YAML-round-trip project-status).
- Disabling a check without a waiver → a `major` "check disabled without waiver".
  An MG-6 waiver requires a plan entry. MG-3/MG-4 fingerprints = manuscript hash.
  `PLAN.md` is never overwritten (new entries append; filled results survive).
  Finding filenames carry the pass: `<subject>.<lens>.p<N>.json`. Findings are
  schema-validated (jsonschema when installed, a minimal fallback otherwise); an invalid
  file → `ERROR`, never a silent drop.
- Generate `GROUNDING.md` and `round-N/REPORT.md` minimally, or remove the promise from
  the docs — pick one and make docs and code agree.

**Profile branch.** For `book-literary`: MG-1, MG-2, MG-3, MG-6 = `n/a (profile)` (no
waiver needed, no probes built). Literary checks: MG-4 (whole-book read, literary mode —
agent), MG-5, MG-7, **MG-S** (`check_story.py --manuscript`: blocking → critical,
major → major), **MG-T** (`lint_fiction.py --book`: major → major, minor → minor, info
ignored), **MG-C** (continuity & developmental audit — agent, findings JSON with
`check: "MG-C"`, `lens: "continuity"|"developmental"`). If S2's scripts are absent,
MG-S/MG-T leave a `blocked` coverage record (v3.3 semantics). Add the new check ids to
the schema. `references/manuscript-gate-literary.md` (D1) documents the literary gate;
`manuscript-gate.md` links to it.

**Language.** `Project.language_variant`: `project.language_variant` →
`conventions.language_variant` → `project.language` → `en-US`. Rule extraction and claim
scoring use `bookkit.lexicon.load(...)` (`modality`, `universal`, `breaks`); when a pack
has no entries, MG-2 falls back to language-agnostic pairing (prose sentences naming a
backticked identifier ↔ code blocks using it). Report "no pack for <lang>" instead of
"0 eligible = complete".

**Text layer.** UTF-8-sig reads, NFC normalization, cp1252 files reported as a `major`
encoding finding instead of a crash; fingerprints keep code spans, operators and case
inside code; rule ids by content hash, not line number; `lint_render` ignores comments
inside code fences, accepts `* * *`/`***` scene breaks, flags `1999.`-style accidental
ordered lists and dialogue glued to narration; `lint_style` respects `dash_style` and
the language (no em-dash rule on dialogue rayas; no English spelling rules on Spanish).

## 6. Literary redesign (D1; D2 summarizes in SKILL.md and pipeline.md)

### 6.1 The user's rules (non-negotiable, no per-project waiver)

- **R1 — Every character has an arc.** Every character (role `protagonist`,
  `principal`, `secondary`) has a complete sheet: backstory, personality, contradiction,
  want, need, voice, and arc (type, start, end, ≥1 turning point assigned to a unit,
  `resolves_in`). A `flat` arc is legal and must name what the character's constancy
  tests or changes (`tests`). No `TBD`.
- **R2 — The story has an ending,** defined before drafting in
  `bible/plot-structure.md` front matter (`ending.resolution`, `ending.answer` to the
  dramatic question, `ending.final_unit`). Every arc resolves at or before
  `final_unit`.
- **R3 — Drafting starts only when every character in the outline has backstory,
  personality and an established arc, and the ending exists.** Mechanically:
  `python scripts/pipeline_step.py ready` must exit 0 before `phase: drafting`. If the
  user asks to start anyway, explain the rule and run the questionnaire for what is
  missing (short answers are fine; empty ones are not).
- **R4 — Characters may be added mid-book, but the questionnaire runs again.** Triggers:
  the human or the Writer proposes a new character; the outline gains a new name;
  `check_story.py --unit` / `lint_fiction.py` reports `NEW-CHARACTER`/`unknown_name`. The
  unit pauses; the orchestrator runs `references/character-questionnaire.md` with the
  human for that character; the full sheet is written (`added_mid_book: true`,
  `added_in_unit`), arcs (turning points and `resolves_in` inside the remaining outline,
  ≤ `final_unit`), the outline (`characters_present`, `arc_moves`) and the story ledger
  are updated; the human signs; the unit restarts at the Writer. **The Writer never
  invents a named character**: it uses an unnamed extra (one unit at most) or writes a
  `WRITER NOTE` requesting a character.
- **Extras:** unnamed incidental figures appearing in at most one unit live in
  `bible/characters/_extras.md`. Named or recurring → a character (R4).

### 6.3 Upstream: Phase 2 design gate
Scene cards (6.2), causal chain between consecutive scenes ("therefore"/"but", never
"and then"), story ledger with planned payoffs, **echo check** on turning points (K
alternatives from fresh subagents given only premise + preceding summary; a chosen
turning point matching the majority is flagged "model default" and discussed with the
human), Reader-POV **outline stress test** (reads the synopsis cold, predicts), and a
computed **design rubric** (`design-*` items in `rubric-literary.md`) presented with the
outline for human approval. Then `pipeline_step.py ready`.

### 6.4 Human taste enters the text
Seeds (`literary.seeds`), braindump preserved (`bible/braindump.md`), at least
`human_calibration_passages` passages written by the human, **key scenes by selection**
(the Writer drafts divergent versions; the human picks), and a short human packet: the
3 most singular and 3 most generic passages, tic counts, reader-journal excerpt, 1–3
decisions — not six reports.

### 6.5 Write by scene, repair by diagnosis
Writer drafts scene by scene from the cards, marked `<!-- SCENE s1 -->`; the Editor
assembles. Humanizer: detect-then-edit by the LAMP categories (cliché, unnecessary
exposition, purple prose, poor sentence structure, lack of specificity, awkward
phrasing, tense inconsistency), spans first, few-shot from **the project's** voice
profile; the 3% budget is verified by `check_role_diff`. A literary tic pass every
`tic_pass_every` approved chapters (`lint_fiction --book` + Humanizer batch →
`apply-edits` yaml).

### 6.6 Honest gate
Scorecard for defects only. Quality signals: isolated Reader-POV on clean text with the
**reader journal** (`bible/reader-journal.md`: expectations, suspicions, open questions,
attachments, 3–5 predictions for the next chapter; predictability is measured against
them), no outline for the literary reader (it spoils beats), pairwise comparison against
the best approved chapter or a human reference passage. CG **Mode A (literary)** before
the gate: continuity against tracker/timeline/world/sheets (ConStory categories:
character, factual detail, narrative style, timeline, plot, world) plus a **facts lane**
when `fact_check: realistic` (dates, results, geography, prices, events: verify or ask).
Literary manuscript gate per §4 (MG-S/MG-T/MG-C).

### 6.7 Remove or relax
Opening rotation → no rotation in literary (lint_fiction `opening_repeat` observation).
VOICE-RISK → optional 0–2 with a risk log in the digest. "Mandatory techniques" that
push purple/staccato prose → diagnostics with budgets (simile density, fragment ratio,
bodily-sensation vs named emotion). Em-dash cap and "said/asked only" → language-aware.
"Inject controlled imperfection" → removed. Commercial-genre craft sources → optional,
chosen by subgenre at setup. Digest "voice calibration samples" → removed (the Writer
must not calibrate against neighbours).
